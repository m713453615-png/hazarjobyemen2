# Hazar-Job.com - هازار للوظائف

منصة وظائف عربية RTL مخصصة للسوق اليمني، مبنية باستخدام React وVite وTypeScript وTailwind CSS وFramer Motion.

## التشغيل المحلي

يتطلب المشروع Node.js 20.19 أو أحدث.

```bash
npm install
npm run dev
```

يفتح Vite الواجهة عادة على `http://localhost:5173`، ويعمل خادم API على `http://localhost:8787`.

## مستويات الصلاحية

- **طالب العمل:** البحث، الفلاتر، تحليل السيرة الذاتية، المطابقة، التقديم، الحفظ، والتنبيهات.
- **صاحب العمل:** الإحصاءات، نشر الوظائف، رفع إثبات الدفع، وإدارة المتقدمين.
- **مالك المنصة:** التحكم الكامل بالوظائف، المدفوعات، المستخدمين، الإعدادات، والتوثيق.

نسخة المالك الخاصة تسمح بالتبديل بين الحسابات الثلاثة. نسختا الويب وAndroid العامتان لا تعرضان حساب المالك أو بياناته الخاصة.

### فصل النسخ العامة عن نسخة المالك

العلم `VITE_OWNER_BUILD` يحدد نسخة البناء، وهو **مفعّل بالاختيار**: أي بناء لا يضبطه يبقى نسخة عامة.

| الملف | الاستخدام | `VITE_OWNER_BUILD` |
| --- | --- | --- |
| `.env` | القيم المشتركة لكل أوضاع البناء | — |
| `.env.public` | النسخة العامة: الويب وAndroid وWindows العام | `false` |
| `.env.owner` | نسخة المالك الخاصة | `true` |

الواجهات الخاصة بالمالك محجوبة داخل كتلة واحدة في `src/App.tsx`، لذلك تُحذف بالكامل من حزمة النسخة العامة أثناء البناء ولا تُنشر مع الموقع. يتحقق CI من ذلك في كل عملية بناء.

> أي متغير يبدأ بـ `VITE_` يدخل داخل حزمة المتصفح ويظهر لكل زائر، فلا تضع فيه أي مفتاح سري. مفتاح المالك يوضع في `إعدادات المالك > الأمان والصلاحيات > مفتاح مزامنة المالك` ويُحفظ على جهاز المالك فقط.

## أوامر المشروع

```bash
npm run dev          # الواجهة وخادم API معاً
npm run build:web    # نسخة الويب العامة
npm run build:owner  # نسخة المالك الخاصة
npm run lint         # فحص ESLint
npm run typecheck    # فحص أنواع الواجهة والخادم وWorker والاختبارات
npm test             # اختبارات وحدة وتكامل وتشغيل كامل للواجهة
npm run check        # lint + typecheck + test
npm run audit:prod   # فحص ثغرات اعتماديات الإنتاج فقط
```

## نسخ البناء

```bash
# موقع ويب عام قابل للتثبيت PWA
npm run build:web

# نسخة المالك الخاصة
npm run build:owner

# مشروع Android عام
npm run android:sync

# مثبت Windows خاص بالمالك
npm run windows:build
```

- `VITE_OWNER_BUILD=false` مستخدم في النسخة العامة.
- `VITE_OWNER_BUILD=true` مستخدم في نسخة المالك.
- إعداد `vercel.json` جاهز لنشر الموقع بعد ربط حساب الاستضافة والدومين.
- Workflow داخل `.github/workflows/codex-integration.yml` يفحص الترميز والبناء ويراجع الفرع.
- يقرأ الموقع وتطبيق Android ونسخة Windows العامة البيانات من API مركزي واحد، ويجري تحديث تلقائي كل 12 ثانية وعند العودة إلى التطبيق.
- راجع `DEPLOYMENT.md` لخطوات نشر Cloudflare وربط النطاق وقاعدة البيانات.

لتوقيع ملف Android المخصص لمتجر Google Play أضف أسرار GitHub التالية داخل مستودع خاص:

- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

## واجهة API

المسارات المتاحة على الخادم المحلي وعلى Cloudflare Worker معاً:

| المسار | الصلاحية | الوظيفة |
| --- | --- | --- |
| `GET /api/health` | عام | فحص جاهزية الخدمة |
| `GET /api/snapshot` | عام | الوظائف والمتقدمون والإعدادات في طلب واحد |
| `GET /api/jobs` | عام | قائمة الوظائف |
| `POST /api/jobs` | عام | نشر وظيفة جديدة (تبقى بانتظار الاعتماد) |
| `PATCH /api/jobs/:id` | المالك | اعتماد أو تعديل وظيفة |
| `DELETE /api/jobs/:id` | المالك | حذف وظيفة |
| `GET /api/applicants` | عام | قائمة المتقدمين |
| `PATCH /api/applicants/:id/status` | عام | تحديث حالة متقدم |
| `POST /api/licenses` | عام | إرسال طلب توثيق منشأة |
| `GET /api/licenses/latest` | عام | آخر طلب توثيق (ليطّلع صاحب العمل على قرار المالك) |
| `GET /api/licenses` | المالك | كل طلبات التوثيق |
| `PATCH /api/licenses/:id` | المالك | اعتماد أو رفض طلب توثيق |
| `GET /api/settings` | عام | إعدادات المنصة |
| `PUT /api/settings` | المالك | تعديل إعدادات المنصة |

طلبات المالك تحتاج ترويسة `Authorization: Bearer <مفتاح المالك>`. الخادم المحلي يفتح هذه المسارات عندما لا يكون `HAZAR_OWNER_TOKEN` مضبوطاً لتسهيل التطوير، ويغلقها فور ضبطه.

## بنية المشروع

- `src/App.tsx`: واجهات التطبيق وتدفقات المستخدمين.
- `src/index.css`: نظام التصميم المتجاوب والوضعان الداكن والفاتح.
- `src/data.ts`: نماذج البيانات والبيانات التجريبية.
- `src/i18n.ts`: قاموس الترجمة العربية والإنجليزية.
- `src/archive.ts`: أرشيف مستندات خاص بالتطبيق باستخدام IndexedDB.
- `src/api.ts`: عميل الاتصال بواجهة API المركزية.
- `server/index.ts`: واجهة API محلية للوظائف والمتقدمين والتوثيق والإعدادات.
- `cloudflare/worker.ts`: نفس الواجهة على Cloudflare Worker مع قاعدة D1.
- `test/`: اختبارات البيانات وواجهة API وتشغيل الواجهة داخل DOM حقيقي.

## الاختبارات

```bash

```

تغطي الاختبارات:

- سلامة البيانات التجريبية ومربوط المتقدمين بالوظائف.

- تشغيل الواجهة فعلياً داخل DOM، مع التأكد من عدم ظهور أي خطأ في وحدة التحكم.
- فتح كل شاشات طالب العمل وصاحب العمل والمالك والتأكد من عملها.

## الانتقال إلى الإنتاج

واجهة API الحالية تستخدم ذاكرة الخادم للتجربة. قبل النشر التجاري، استبدلها بقاعدة PostgreSQL، تخزين ملفات متوافق مع S3، مصادقة آمنة تعتمد جلسات HTTP-only، وخدمة بريد وإشعارات. يجب أيضاً نقل تحليل السير الذاتية إلى خدمة خلفية محمية وعدم كشف مفاتيح نماذج الذكاء الاصطناعي في الواجهة. ربط `Hazar-Job.com` يتطلب صلاحية حساب مسجل النطاق وتعديل DNS.
